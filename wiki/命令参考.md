# 命令参考

全部子命令、选项、输出格式与退出码。命令的行为机制见《工作原理与性能》，报错处理见《常见问题》。

## 子命令

```text
blocksync sync <输入目录> <输出目录> [--dry-run] [--full] [--verify]
      把输入目录增量镜像到输出目录；反向同步交换两个参数的顺序。
blocksync setup                交互录入或修改本机两个目录（首次必做）
blocksync setup --show         查看当前配置
blocksync status [<目录>]      查看该目录的索引覆盖情况
blocksync verify [<目录>]      全量重算哈希，检查磁盘内容与索引是否一致
blocksync repair [<目录>]      按磁盘实际内容重建索引
blocksync version              显示版本号
```

`version` 也可以写作 `-v` 或 `--version`；帮助文本首部同样列出当前版本。版本号只定义在 `internal/version/version.go`，CLI 与 GUI 共用。

省略目录参数的命令（status/verify/repair）读取 `setup` 保存的本机配置；`sync` 始终要求显式给出两个目录。

`sync`、`verify`、`repair` 的排除规则一致：内置默认 + 该目录所属目录对的配置规则（见《排除列表》§4）。

## 选项

| 选项 | 说明 |
|---|---|
| `--dry-run` | 测试比对：逐文件报告状态与变化量并汇总读取/预计写入，不写数据文件、不更新索引（目标索引失效时仍会重扫目标以获得真实哈希，这部分读取会计入汇总） |
| `--verify` | 写入后复读校验：每写一个文件立即重读并重算哈希对照 |
| `--full` | 忽略修改时间，全部文件重读重算（源索引一律按失效处理） |
| `--workers N` | 单文件内部哈希并行度，默认 CPU 核数 |
| `--lb BYTES` / `--sb BYTES` | 粗块/细块大小，默认 4194304 / 32768；`LB > SB` 且 `LB % SB == 0`，两侧必须一致 |
| `--force` | 删除上次异常退出遗留的 `.blocksync\lock` 后接管 |
| `--yes` | 跳过首次同步与删除前的人工确认（脚本无人值守） |
| `--allow-mass-delete` | 删除数量超过安全上限（`max(100, 源文件总数 × 1%)`）时仍继续；GUI 无此开关，超限时弹窗询问后自动带上 |
| `--quiet` | 不输出逐文件进度行 |
| `--log-file 路径` | 把本次全部输出（stdout 与 stderr，含进度与错误）另写一份到该文件；父目录不存在会自动创建。首尾各有一行 `=====` 边界，记录时间、版本、参数与退出码，便于按运行定位 |

选项写在位置参数前后均可（内部会先把选项移到位置参数之前），`--选项=值` 与 `--选项 值` 两种写法都支持。

`--log-file` 是全局选项，任何子命令都可带。它不改变终端输出，只是多存一份；`> 文件` 只收 stdout 会漏掉进度与错误，需要留档时用它代替重定向。图形界面不使用该选项，界面会自行把子进程输出写进自己的日志文件（见《图形界面》§2）。

## 输出格式

`sync` 的逐文件行（`--quiet` 时不输出），字段之间固定两个半角空格：

```text
[i/N] 状态  相对路径  [（原因）]  [说明]
```

- 状态取值：`哈希计算`（附文件体积）、`新增`（附文件体积）、`更新`（`变化 X / 共 Y`；只需截短时为 `截断到 X`，X 为 0 即清空）、`无变化`、`删除`（`（源端已不存在）`）。
- 结果行只有新增、更新、删除三类；变短与清空并入更新，用说明区分。
- `哈希计算` 行在整文件读取开始前打印，与该文件的结果行同号。凡是需要整文件读取的文件都会打印：源索引失效重读源、目标索引失效重扫目标、新文件且源索引不可信时的一遍读取与复制。实际读取量为 0（如空文件）时不打印。`--quiet` 时不输出。
- 序号连续覆盖全部待处理文件（改动与删除），不跳号；分母 N 与汇总行「扫描 N 个」一致。
- 目标已有该文件、但源索引不可复用时，原因紧跟在路径之后；取值与产生条件见《工作原理与性能》§5.3。

每个文件处理结束后再补一行完成标记（`--quiet` 时同样不输出）：

```text
[i/N] 完成  相对路径
```

`哈希计算` 行在读取之前、结果行在写入与校验之前打印，完成行在写入与校验之后：大文件的读取与写入期间没有其他输出，这三行用来区分「正在计算」「正在处理」与「已处理完」，也便于判断失败卡在哪个文件。完成行与结果行同号；`删除` 的条目同样带完成行。dry-run 没有写入动作，只输出结果行，不输出完成行。

进入逐文件处理前先输出一行开始提示：确认通过、`--yes` 跳过确认或本次无需确认时为 `同步任务开始…`，dry-run 为 `测试比对开始…`。首个文件的整文件读取可能持续数分钟，紧随其后的 `哈希计算` 行表示已开始读取；`--quiet` 时同样不输出。

每次运行的最后一行为汇总行：

```text
完成：扫描 N 个，改动 N 个，删除 N 个；读取 X，写入 Y，耗时 T
完成（测试比对）：扫描 N 个，改动 N 个，删除 N 个；读取 X，预计需写入 X（未改动任何数据），耗时 T
```

「读取」是两侧的全部读入：源扫描、目标重扫、新文件复制、区间复制的读入、写入后校验的读回都计入；「写入」是实际写出的字节数。无改动时不输出上面的汇总行，改为 `已是最新：N 个文件均无变化，耗时 T`（dry-run 为 `测试比对：N 个文件均无变化，未改动任何数据，耗时 T`）。耗时截断到秒（`12m59.994s` 显示为 `12m59s`），不足 1 秒显示 `0s`。

逐文件进度行与汇总行同时是 GUI 的解析输入，改动写法需同步界面侧（见《图形界面》§2）。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（包括「已是最新」这类提前返回，都会走 0） |
| 1 | 失败：同步/校验出错、参数错误、用户取消确认 |
| 2 | 未给出或无法识别子命令（`--help` 正常输出并返回 0） |
