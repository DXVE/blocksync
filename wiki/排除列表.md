# 排除列表

排除列表决定哪些文件**不参与同步**：不读取、不计算哈希、不进入索引，目标侧已有的同名文件也不会因「源端不存在」而被镜像删除。本文说明规则来源、匹配算法的精确语义、配置的存放与迁移。

## 1. 规则的两个来源

一次同步使用的排除规则是两组的先后拼接（`cmd/blocksync` 的 `loadExcludes`）：

1. **内置默认规则**（`scan.DefaultExcludes`，永远在最前面，不可被配置覆盖）：`.blocksync`（工具自身状态目录）、Windows 系统目录（`$RECYCLE.BIN`、`System Volume Information`、`$WinREAgent`、`Config.Msi`）、系统文件（`desktop.ini`、`Thumbs.db`、`pagefile.sys`、`hiberfil.sys`、`swapfile.sys`）。
2. **按目录对的配置规则**（`config.json` 的 `excludeSets`），由界面「配置管理…」编辑。`sync`（无论方向如何）读取本地目录对的这一组规则；`repair` 只拼内置默认规则（见 §4）。

图形界面首次打开排除配置对话框时，若该目录对尚无记录会写入一张示例列表（系统目录、回收站、休眠文件等），用户可删改；全部删空并保存后该目录对保持为空，不会被再次自动补回（`seedExcludes` 只在记录完全不存在时生效）。

## 2. 规则语法

一行一条，`#` 不作注释符（所有非空行都按规则解析）。`\\` 不需要转义，第一个 `\` 起就被当作分隔符处理。

| 写法 | 含义 |
|---|---|
| `\System Volume Information\` | 行首 `\` 锚定根目录；行尾 `\` 表示目录本身，命中后整棵子树排除 |
| `\$Recycle.Bin\` | 锚定根目录的目录规则，Windows 下不区分大小写 |
| `\RECYCLE?` | `?` 匹配单个字符；`*` 匹配不含分隔符的任意分段 |
| `*\thumbs.db` | 不锚定时匹配任意层级 |
| `*\.git\` | 任意层级名为 `.git` 的目录及其全部内容 |
| `cache` | 纯名字（无通配符、未锚定、非目录尾）：任意层级出现同名文件或目录都排除 |

### 2.1 解析（`scan.parseRule`）

空行无效。单条规则的逐步处理：

1. 两端去空白。
2. `\` 全部替换为 `/`（同时统一了 Windows 路径与模式写法）。
3. 行首 `/` → 锚定根目录，记为 `anchored` 并去掉该字符。
4. 行尾 `/` → 目录规则，记为 `dirOnly` 并去掉该字符。
5. 结果只剩 `.` / `..` 的规则无效。
6. Windows 下整个模式转小写。

### 2.2 匹配算法（`scan.matchRule`）

被比较的是被同步条目的**相对路径**（斜杠分隔，Windows 下同样转小写）。规则分三类匹配：

- **纯名字规则**（无 `* ? [` 通配符、未锚定、非目录尾）：命中三种情况——相对路径整体相等、相对路径以名字开头并紧跟 `/`（子树）、或路径的任意一段与名字相等。即一条 `cache` 排除任意层级的该名字。
- **目录规则**（`dirOnly`）：考察相对路径本身与其每一级祖先目录，任一级命中模式即排除整个子树。
- **路径模式**（其余）：整体匹配相对路径；未锚定时还会对路径的每一级后缀（去掉前几段后的余下路径）逐一尝试，等价于「匹配任意层级」。`*` 不跨越 `/`，要匹配跨层需要显式写路径或「名称+目录尾」写法。

锚定规则的比较对象是相对路径的**完整形式**（`matchAtLevels` 的候选里包含直接比较）；通配符语义来自 `path.Match`：`*` 匹配任意一段非分隔符字符序列、`?` 单个字符、`[...]` 字符类。

界面在保存前对每行调用 `scan.ValidatePattern` 做语法校验（只查通配符合法性），不符合的行会弹窗报出行号。

### 2.3 非排除过滤

排除规则之外还有一条固定过滤：**非普通文件不参与同步**。符号链接、设备文件等在源端枚举时即被跳过并计入跳过列表。`.blocksync` 由内置默认规则排除，内置规则始终拼接且不可被配置移除，因此在界面里删掉同名行也不会让它进入同步范围。

## 3. 配置保存与排除的传播

### 3.1 config.json 的结构

按目录对（无序）保存在 `%LOCALAPPDATA%\blocksync\config.json`：

```json
"excludeSets": [
  { "a": "d:\\data\\project", "b": "e:\\backup\\project", "excludes": ["..."] }
]
```

- 键无序：`SamePair` 用两侧路径规范化后字典序比较（规范化 = 绝对路径 + `Clean` + Windows 转小写 + 排序），所以交换两个目录、反向同步命中的永远是同一组规则。
- 多个具名配置（`profiles`）指向同一个目录对时**共用**这一份规则，规则不随配置复制。
- 该文件同时保存生效目录对与具名配置，结构见《工作原理与性能》§2.2。

### 3.2 配置迁移（`MigrateExcludes`）

在「配置管理…」中把某配置的目录改到新路径时，规则跟随配置搬到新的目录对：先把规则登记到新目录对，再从旧目录对删除——**仅当旧目录对不再被其他配置引用**时才删除；旧规则在别处仍在使用时原样保留。

### 3.3 与旧版格式的兼容

旧版把规则存在各同步目录的 `.blocksync\config.json` 里，**已停用**且不再读取。存在该文件时程序只打一行提醒（`warnLegacyExcludes`）；升级后请把规则迁到本机配置，否则原先排除的条目会重新进入同步范围。

## 4. 行为细节

- 目录规则命中后，遍历以整棵子树剪枝（`fs.SkipDir`）结束，子树内容完全不被触碰。
- 命中的条目计入日志最后一行的「按排除规则跳过 N 项：…」，最多列出 6 项，其后以「…」收尾；这一行同时是核对规则是否生效的最快途径。
- 「扫描 N 个」 与逐文件行 `[i/N]` 的分母相同，即扣除排除项后的源文件总数。
- 被排除文件若残留索引条目，`verify` 不会把它报成「多余索引」；真正的清理由 `sync` 与 `repair` 完成。
- `sync`、`verify`、`repair` 使用同一套规则：内置默认 + 该目录所属目录对的配置规则。单目录命令按目录在排除规则表里查找所属目录对，不依赖配置项是否仍存在；目录不在任何目录对中时只用内置默认规则。本机配置读取失败时在 stderr 提示一行，并按「只有内置规则」继续。
