# 常见问题

按「看到提示怎么办」「同步比预期慢怎么查」组织。命令、选项与输出格式见《命令参考》，工作机制见《工作原理与性能》。

## 提示语对照

| 提示 | 含义与处理 |
|---|---|
| `目录不存在：…` | 盘符变化或路径填错。改用显式路径重试，或重新 `setup` |
| `目录正被另一个 blocksync 进程使用（…）` | 该目录的 `.blocksync\lock` 已被占用。确认没有其他实例（包括 GUI）在跑之后加 `--force`；GUI 检测到锁失败时会弹窗说明并发写入的后果，默认选「否」，确认没有其它窗口在同步后再选「是」接管锁重试。锁的机制见《源目录保护》§6 |
| `输入目录与输出目录相同` / `输出目录位于输入目录之内` / `输出目录包含输入目录` | 拓扑校验拒绝，改用互不包含的两个目录（见《源目录保护》§1） |
| `已阻止写入 …：该路径位于输入目录内` | 写入前句柄核验发现目标最终位置落进输入目录，多因运行中出现的目录联接。已中止，请检查目标子树 |
| `已阻止写入 …：该路径不在输出目录内` | 同上，目标解析出了输出目录之外的最终位置 |
| `已阻止写入 …：该文件有 N 个硬链接` | 目标是多链接文件，写入会改坏其他路径，已中止 |
| `源文件与目标文件是同一份数据，已阻止写入` | 源与目标在磁盘上是同一份数据（硬链接/联接别名） |
| `写入后内容与源不一致：…` | `--verify` 写后复算失败：介质写入不可靠或目标被并行修改。已中止整次同步 |
| `本次将删除 N 个文件… 超过安全上限` | 删除量达到事故特征值，先 `--dry-run` 确认方向与目录，再决定是否 `--allow-mass-delete` |
| `未获得确认：当前不是交互终端` | 脚本/管道场景无法回答确认，确认无误后加 `--yes` |
| `块大小非法：…` | `--lb/--sb` 不满足 `LB>SB` 且整除 |
| `提示：… 索引损坏，将自动重扫` | 该文件的 `.idx` 无法解码。忽略本条并重扫重写；个别损坏不影响其他文件，无需处理（格式见《工作原理与性能》§4） |
| `本机尚未配置` | 需要目录参数的命令没有给目录且 `setup` 未配置过，先录配置 |
| `verify` 报告 `内容不符`/`缺少索引`/`索引损坏`/`多余索引` | 逐个文件列出原因，结尾汇总不一致总数。`内容不符` 后括注「N 个细块不一致」表示内容变化，括注「文件长度与索引记录不同」表示长度变化。文件内容确为最新时执行 `repair` 重建索引；或用 `--full` 同步一次让索引与磁盘重新对齐 |
| `open …: Access is denied`（recycle/系统目录下） | 检查对象是 Windows 系统目录，当前版本已内置排除；仍出现说明走了旧版程序或目录被改名 |

## 日志去哪儿找

- 图形界面：`%LOCALAPPDATA%\blocksync\logs\` 下按启动时间命名的 `gui-*.log`，一次启动一个文件，保留 7 天、总量不超过 200 MB；界面日志区按表格显示最近约 50 万字符，更早的行只在文件里。每次运行由 `===== … sync … =====` 与 `===== 结束：… =====` 包住，按这两行定位。
- 命令行：默认只输出到终端。要留档加 `--log-file 路径`（标准输出与标准错误都会写进去）；用 `> 文件` 重定向只会收到 stdout，进度与错误在 stderr 上会漏掉，要写全用 `> 文件 2>&1`。
- 命令行中文乱码：旧代码页的 cmd 不认 UTF-8，先 `chcp 65001`，或改用 Windows Terminal。

## 速度不达预期时的诊断

1. 看逐文件行的括号原因。大量 `（源文件修改时间变化）` 属正常；大量 `（源索引不存在）` 说明索引在重建（首次同步、`repair` 后）或被外部清理。
2. 结尾汇总的「读取」远大于预期而改动很小：先确认不是 `--full` 挂着；再看是否对方目录最近被外部程序碰过（哪怕只改一个字节也要重扫一侧）。
3. 「写入」接近全量而实际只改了几处：把大块的连续改动区段与实际痕迹核对（可用《演练与部署》的 `模拟改动.ps1` 对测试副本复现），常见于「文件中间插入字节导致位移」型改动（Office 保存、日志回卷），属按偏移比对的固有代价。
4. CPU 占用高属预期，成本构成见《工作原理与性能》§9；`--workers` 高于核数没有收益。
